# SurfaceRT-WiDi — تبدیل Surface RT به مانیتور بی‌سیم

[English](README.md)

> هدف: تبلت Surface RT (ویندوز RT 8.1، پردازنده Tegra 3) به‌عنوان **صفحه‌نمایش
> بی‌سیم** برای یک کامپیوتر ویندوز ۱۰/۱۱ استفاده شود و **روی کامپیوتر هیچ چیز
> نصب نشود**.

## اول از همه: چه چیزی ممکن است و چه چیزی نه

«Wireless display» خود ویندوز (همان `Win+K` → Connect) فقط گیرنده‌های
**Miracast** را نشان می‌دهد، و گیرنده Miracast باید یک **Wi-Fi Direct peer** باشد.
ویندوز RT 8.1 این نقش را به هیچ برنامه‌ای نمی‌دهد:

1. مایکروسافت قابلیت «Miracast Receive» را فقط به‌صورت یک **مجموعه API مخصوص
   سازندگان درایور وای‌فای (IHV/OEM) و فقط برای برنامه‌های x86/x64** منتشر کرد
   (آپدیت آگوست ۲۰۱۴) — نسخه ARM هرگز ساخته نشد.
2. حتی «Miracast over Infrastructure» (استاندارد MS-MICE، پورت TCP 7250) هم ابتدا
   نیاز به **بیکن/Probe-Response وای‌فای دایرکت با Information Elementهای WSC**
   دارد؛ یعنی کنترل فریم‌های خام ۸۰۲.۱۱ که در RT به هیچ برنامه‌ای داده نمی‌شود.

مستندات و منابع کامل: [docs/FEASIBILITY.md](docs/FEASIBILITY.md)

پس این پروژه بهترین گزینهٔ عملی را به‌صورت کامل پیاده کرده است:

> یک **گیرندهٔ واقعی نمایش بی‌سیم** روی تبلت به‌شکل سرویس ویندوز + یک **فرستندهٔ
> بدون‌نصب** برای ویندوز ۱۰/۱۱ که فقط از اجزای خود ویندوز استفاده می‌کند
> (GDI برای تصویر، System.Drawing برای JPEG، سوکت برای انتقال).
> تأخیر حدود ۴۰ تا ۸۵ میلی‌ثانیه، ۱۲ تا ۲۰ فریم بر ثانیه در ۱۳۶۶×۷۶۸،
> با تنظیم خودکار کیفیت و امکان استفاده از لمس تبلت به‌جای ماوس کامپیوتر.

## امکانات

- **روی تبلت:** برنامهٔ تمام‌صفحه، سرویس ویندوز با استارت خودکار، اجرای مجدد پس
  از کرش، روشن نگه‌داشتن صفحه، اعلام حضور در شبکه (beacon)، نمایش وضعیت و لاگ.
- **روی کامپیوتر:** فقط یک اسکریپت PowerShell؛ کلاس کمکی **در حافظه** کامپایل
  می‌شود (Add-Type) — نه نصب، نه رجیستری، نه فایل باقی‌مانده.
- **تنظیم خودکار:** تبلت زمان رمزگشایی و تعداد فریم‌های ازدست‌رفته را گزارش
  می‌کند؛ فرستنده اول نرخ فریم، بعد رزولوشن و بعد کیفیت JPEG را کم می‌کند و در
  صورت وجود ظرفیت دوباره بالا می‌برد.
- **پروتکل مقاوم:** CRC32 برای هر پیام، همگام‌سازی مجدد با یک بایت خطا، بافر
  محدود و سیاست «آخرین فریم برنده است» تا تأخیر انباشته نشود.
- **لمس:** کشیدن انگشت روی تبلت، ماوس کامپیوتر را حرکت می‌دهد (پشتیبانی از چند
  مانیتور).
- **تست‌شده:** ۲۲ تست و حدود ۴۲۰۰ اَسِرشن (ASan/UBSan هم پاک)، شامل استریم واقعی
  روی TCP، تست fuzz و اعتبارسنجی
  بایت‌به‌بایت انکودر سمت کامپیوتر.

## شروع سریع

### ۰) با یک دستور (بدون IDE، بدون SDK، بدون نصب چیزی)

```
build.cmd            # ویندوز: هر کامپایلری که باشد پیدا می‌کند و فرستنده را همیشه می‌سازد
build.cmd test       # به‌همراه کل تست‌های هستهٔ C++
./build.sh test      # لینوکس / مک / WSL
```

حتی اگر روی ویندوز **هیچ** کامپایلر C++ نصب نباشد، `build.cmd` باز هم
`tools\pc\widi-pc.exe` را می‌سازد، چون از کامپایلر C# که خودِ .NET Framework در
`%WINDIR%\Microsoft.NET` دارد استفاده می‌کند. توضیح کامل:
**[docs/BUILD-ONELINE.md](docs/BUILD-ONELINE.md)**

### ۱) تبلت (Surface RT جیل‌بریک‌شده — [docs/BUILD-RT.md](docs/BUILD-RT.md))

```
build\winrt8\build_rt.cmd
.\install\Install-WiDiService.ps1 -SourceDir C:\widi\build\winrt8
```

### ۲) کامپیوتر ویندوز ۱۰/۱۱

نسخهٔ کامپایل‌شده (پیشنهادی):

```
tools\pc\Build-Sender.cmd           # یک خط، با کامپایلر C# خود ویندوز
.\tools\pc\widi-pc.exe              # پیدا کردن تبلت و شروع پخش
.\tools\pc\widi-pc.exe --list       # فقط نمایش دستگاه‌های پیدا شده
.\tools\pc\widi-pc.exe --selftest   # بررسی صحت پروتکل، بدون نیاز به تبلت
```

یا نسخهٔ PowerShell (آن هم بدون نصب، و بدون مرحلهٔ کامپایل):

```powershell
.\tools\pc\Send-Screen.ps1          # پیدا کردن خودکار تبلت و شروع پخش
.\tools\pc\Send-Screen.ps1 -List    # فقط نمایش دستگاه‌های پیدا شده
```

با `Ctrl+C` متوقف می‌شود و هیچ اثری روی کامپیوتر نمی‌ماند.

### ۳) تست بدون هیچ دستگاه ویندوزی

```bash
make test        # ۲۲ تست، حدود ۴۲۰۰ اَسِرشن
make             # ساختِ گیرندهٔ مرجع و فرستندهٔ آزمایشی
./out/widi-sink-linux --port 47000 &
./out/widi-sender-linux --host 127.0.0.1 --port 47000 --frames 60
python3 tools/dev/wire_check.py --port 47000
```

## محدودیت‌های واقعی (صادقانه)

| محدودیت | دلیل |
|---|---|
| در `Win+K` دیده نمی‌شود | روی RT 8.1 غیرممکن است ([FEASIBILITY](docs/FEASIBILITY.md)) |
| تصویر Mirror است، نه Extend | حالت Extend نیاز به درایور نمایشگر روی کامپیوتر دارد |
| محتوای محافظت‌شده (HDCP) سیاه دیده می‌شود | RT هیچ HDCP ندارد |
| سقف کیفیت حدود ۱۳۶۶×۷۶۸ | توان رمزگشایی JPEG پردازندهٔ Tegra 3 |
| پروتکل نسخهٔ ۱ رمزنگاری ندارد | فرض شبکهٔ خانگی مطمئن؛ DTLS در نقشهٔ راه |
| نیاز به ورود کاربر در تبلت | سرویس ویندوز در session 0 نمی‌تواند پنجره بسازد |
| نیاز به جیل‌بریک | Windows RT فقط باینری‌های امضاشدهٔ مایکروسافت را اجرا می‌کند |

## وضعیت واقعی تحویل

| مورد | وضعیت |
|---|---|
| هستهٔ قابل حمل (پروتکل، سشن، موتور، تنظیم نرخ) | ساخته و تست‌شده روی لینوکس: ۲۲ تست، بدون خطا، ASan/UBSan پاک |
| گیرندهٔ مرجع + فرستندهٔ آزمایشی روی TCP واقعی | تأیید شد (۲۴ از ۲۴ فریم، بدون افت) |
| لایهٔ ارتباطی فرستندهٔ ویندوزی | با `tools/dev/wire_check.py` بایت‌به‌بایت تأیید شد |
| کامپایل فرستنده با کامپایلر C# خود ویندوز | تأیید شد: `csc` با C# 5 روی reference assemblyهای .NET Framework 4.8، بدون خطا |
| `widi-pc.exe --selftest` | تأیید شد: ۳۳ از ۳۳ بررسی موفق |
| هندشیک واقعی فرستندهٔ C# با گیرندهٔ مرجع | تأیید شد (Hello/HelloAck/Bye پذیرفته شد و لاگ گیرنده نام و ابعاد را ثبت کرد) |
| باینری‌های ویندوز RT | کد کامل است؛ باید با VS2013 + SDK 8.1 برای ARM ساخته و روی دستگاه تست شود |
| تست روی سخت‌افزار واقعی Surface RT | در این محیط انجام نشده (دستگاه موجود نیست) |
